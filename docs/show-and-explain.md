# «Покажи и объясни»

Семейная игра в существующей игротеке `/games`. Общий экран показывает поле и
результаты, телефоны получают личные задания через привычные комнаты и QR-коды.
Комнату можно создать из каталога; её тип API — `activity`, общий экран —
`/games/activity/<код>`, телефоны — `/games/join/<код>`.

## Правила и собственные решения

За основу механики взяты предоставленное пользователем техническое задание и
[официальная инструкция Piatnik №602825, ©2002/2015](https://www.piatnik.com/uploads/media/default/0001/01/d8de6a10a3c616d1162ed3c0583b31ff9e909bcb.pdf).
[Страница издателя](https://www.piatnik.com/spiele/marken/activity/activity-original)
подтверждает минуту на задание; содержимое новой редакции с правилами старой не
смешивалось. Поле, название, палитра, интерфейс и все задания созданы для проекта;
коммерческие карточки, изображения и логотипы не использованы.

Играют 2–4 команды, минимум по двое (4–16 участников), либо ровно трое каждый
за себя. На общем экране задают состав, названия, первых ведущих, начинающую
сторону и договорённость о точности ответа. Ведущие чередуются внутри команды.
После неудачи очередь также передаётся.

Поле: START=0, клетки 1…48, FINISH=49. Шесть категорий циклически чередуют
рисование, объяснение и пантомиму; каждая обозначена цветом, значком и текстом.
На START каждый раз можно выбрать любое из шести заданий полученной карточки.
Далее категорию задаёт клетка. Выбранную сложность 3/4/5 и полученную карточку
заменить нельзя. Запоминание занимает примерно 10 секунд, выполнение — 60.
Для обычного командного раунда ведущий может явно открыть карточку соперникам.
В открытом раунде и режиме втроём такой показ исключён.

Обычный успех даёт команде +сложность. Открытый раунд: угадала своя команда —
+6; чужая — ей +4 и команде ведущего +2. Втроём ведущий и угадавший получают
+сложность. Сам ведущий не может быть угадавшим. Неудача и нарушение дают ноль;
при нарушении аннулируется продвижение всех получателей текущей попытки.

Следующие договорённости относятся к собственной цифровой версии:

- Все получатели двигаются одной транзакцией от общих исходных позиций.
  Получатели не вытесняют друг друга. При посадке на неподвижные чужие фишки
  каждая отходит на одну клетку, без цепных вытеснений. START и FINISH исключены.
  Прохождение промежуточных клеток ничего не вызывает. Втроём вытеснений нет.
- Достижение или превышение 49 завершает игру. Фишки остаются на FINISH;
  журнал сохраняет фактическое продвижение. Возможна совместная победа.
- Результат назначает человек на общем экране: исход, угадавший, предварительный
  расчёт, затем подтверждение. До подтверждения можно исправлять. Устную речь,
  корни слов и жесты программа не оценивает. Истёкшая минута открывает судейство:
  люди подтверждают, был ли правильный ответ произнесён вовремя.
- На ход расходуется одна карточка. У каждой сложности собственный порядок и
  сброс. Перемешивается только сброс исчерпанной колоды.
- Отмена возвращает весь последний подтверждённый ход: позиции, очередь,
  ведущего, колоды и журнал. Следующая незавершённая попытка также отбрасывается.
  Это одна ступень отмены; новый идентификатор попытки отклоняет старые команды.
- Телефоны заменяют передачу одного устройства из исходного описания, сохраняя
  существующую концепцию телевизора и личных контроллеров.

Рисовать можно пальцем на телефоне с передачей на телевизор или на бумаге.
На холсте есть перо, ластик, три толщины, отмена штриха и очистка с подтверждением.
Для объяснения нельзя использовать однокоренные слова и переводы; для рисунка —
буквы и цифры; для пантомимы — речь, звуки и указание на предметы. Спорные
ответы участники обсуждают по выбранной до партии договорённости.

## Данные и устройство

`app/data/activity_ru.json` — собственная русская демонстрационная колода:
90 карточек, по 30 на сложность, 540 уникальных заданий. У 108 заданий (20%)
заранее задан `isOpenRound`; открытость не зависит от оформления или броска.
`Card`: id, locale, difficulty, tasks по шести categoryKey.
`Task`: id, text, isOpenRound. Новые наборы добавляются данными с уникальными
идентификаторами и тем же контрактом; загрузчик `activity_data.py` проверяет
полноту, количество и точные дубли. Пока подключён один русский набор.

`activity_types.py` описывает Participant, Player, Team, Cell, Card, Task, Deck, Turn,
TurnResult, MoveTransaction, GameEvent, GameSettings и GameState. Отображение
координат отделено от индекса клетки. `activity.py` содержит правила и чистый
расчёт продвижения; `activity.js` — представление, таймер и отправку действий.
Рисование ограничено 300 штрихами и 12000 точками на попытку.

Существующее хранилище комнат сохраняет состояние, колоды, абсолютные deadline,
журнал, рисунок и снимок отмены. Ревизии и сериализация записи защищают применение
хода от повторной доставки и одновременного нажатия. Рисунок передаётся отдельными
идемпотентными частями с идентификаторами попытки и операции. При обрыве
неподтверждённые части ожидают повторной отправки, доступна кнопка повтора;
перезагрузка до подтверждения сервером может потерять эти части.

На reload телефон сначала показывает нейтральный экран восстановления; задание
нужно открыть явно. Секреты выдаются сервером только уполномоченному телефону,
а не скрываются одним CSS. Телевизор не получает текущий текст задания.
Публичный журнал содержит использованные задания после подтверждения хода.
Время считается от server deadline, поэтому скрытая вкладка и reload не добавляют
секунд. Звук требует обычного взаимодействия с браузером. Повреждённое сохранение
показывает понятную ошибку без автоматического обнуления.

Для проверки откройте локальный `/games`, создайте комнату и подключите нужное
число телефонов. QR должен содержать доступный им адрес сервера. Локальный сервер
должен слушать `0.0.0.0`; доступ через интернет требует опубликованного сервера.
Срок жизни комнат задан существующим общим механизмом: 24 часа.

## Проверки

```sh
venv/bin/python -m unittest discover -s tests -p 'test_*.py'
node --test tests/js/*.cjs
node --check static/activity.js
```

`test_activity.py` проверяет независимые примеры движения, вытеснений, открытых
раундов, совместной победы, приватности, часов, исчерпания колод, отмены,
восстановления, рисования и конкурентного подтверждения через HTTP API.

Визуальная проверка выполнена в браузере при 1280×720: создание комнаты,
приватный показ, рисование, расчёт, подтверждение, отмена и восстановление.
Инструмент браузера не применил запрошенный размер 390×844, поэтому узкую
раскладку нужно дополнительно проверить на физическом телефоне.
